# 文档配图设计

## 从参考图中提炼原则

参考图提供视觉方向，不是必须复刻的模板。下列模式可单独使用或组合；具体画风、配色和布局应适应读者、内容和文档体裁。本指南独立可读，不依赖原始参考图片。

| 参考模式 | 视觉设计 | 信息组织 | 阅读收益与风险 |
|---|---|---|---|
| 手绘成果信息图 | 浅底、彩色描边、轻手绘标题、放大的关键数字、短结论色带 | 按成果类别分区，各区突出一个结果，指标配语义图标 | 快速定位成果和量级；需保留单位、口径与来源，不能用装饰制造增长印象 |
| 分层架构信息图 | 整齐对齐、统一线性图标、层级色条、外围闭环箭头 | 先按职责分层，再呈现层内模块，外围表达反馈与数据回流 | 有助建立系统全貌；文字容易过密，应拆成总览与局部详图 |
| 流程与职责并排解释图 | 柔和背景、圆角节点、主次分明的箭头、少量手绘线条 | 一侧呈现状态或任务流转，另一侧解释职责和能力 | 将“如何运转”和“负责什么”对照阅读；侧栏须与流程节点可对应，避免无关列表 |
| 卡片式阶段信息图 | 统一卡片、彩色标题带、可识别图标、卡内小示意图 | 每卡一个阶段，卡内展示输入、处理和输出，卡间连接成主线 | 扫读容易、便于逐步解释；换行后需编号或跨行箭头，不能让读者猜顺序 |

共同原则是：标题建立主题，分区组织内容，大小与对比表达重要性，图标帮助识别角色，箭头解释关系，短文案减轻阅读负担。浅米色、手绘描边、荧光笔色带和星星装饰只是可选风格，不是可读性的必要条件。

## 配图设计流程

### 1. 确定图的阅读任务

为每张主要配图确定一个核心问题，如“数据怎样回流”“三个方案差异在哪里”“哪个阶段需要人工确认”。明确放置章节和目标显示宽度。不要直接把整节正文交给生图工具。

### 2. 提炼图内内容

从已核验正文提取必须保留的实体、关系、数字、单位和关键限定，形成短标签与说明。详细论证留在正文，图内保留能解释关系的最小充分信息。来源可放图注或附近正文，但必须能对应到具体指标。

正文与图共用同一套事实。示意图可以抽象细节，但不能改变关系、添加未经证实的模块或夸大结论。参考图的业务文案和数字不作为新图的事实来源。

### 3. 选择布局和视觉语言

- 比较用对齐的并列布局，流程用有明确方向的路径，层级用嵌套或分层，反馈用带条件的回路。卡片数量跟随内容，不强制四宫格或六宫格。
- 用空间接近、容器边界和对齐表达分组。先让黑白结构可读，再用颜色辅助识别。
- 同类实体采用一致的图标、形状和颜色；颜色不能是唯一编码。主路径、反馈路径和异常路径使用标签或线型区分。
- 选择少量协调的分区色和一个主要强调色。需要亲和力时可用浅色底、扁平插画、轻手绘边框；正式架构可用规整线条和克制的色条。
- 图标应解释角色或行为，例如存储、搜索、审核、人工等待。陌生图标加文字，装饰不抢占关键文字空间。
- 标题、区域标题、标签形成可辨认的字号层级。手写感适合标题与少量强调，密集正文优先清晰字体。留白分隔信息，不缩小字体硬塞内容。
- 图内高亮结论是视觉入口，不取代证据；与文档摘要分工，避免重复一整段结论。

### 4. 按精确性与维护需求选择制作方式

| 方式 | 适合 | 核验重点 |
|---|---|---|
| 图像生成 | 概念插画、视觉隐喻、少量文字的解释图、风格素材 | 逐项检查文字和事实，特别是数字与关系；不要把整图生成当作准确排版保证 |
| 原生画板／SVG／HTML | 密集文字、精确数据、多关系架构、需要维护的图 | 字体、布局和连线精确；转换或嵌入后再次检查 |
| 混合制作 | 既需插画表现又需精确标签与关系 | 生图制作图标或背景，画板或程序排版文字、数字和连线，检查最终合成效果 |

图像生成是文档配图的正式选项。能提高概念理解或角色识别时应主动考虑，不把所有图退化成方框。但统计图的数据位置和比例必须由真实数据控制；生成素材不能冒充截图、测量结果或历史记录。

### HTML 源稿与跨格式复用

对定制架构、流程、卡片和比较图，默认使用 HTML/CSS 配合内联 SVG 组织源稿，复用同一份文案、数据和布局定义：

1. 目标平台及当前工具支持 HTML 嵌入时，直接嵌入并检查文档内效果。无需为了“配图”再导出另一份静态文件。
2. 无法嵌入 HTML 时，优先输出真正的静态 SVG。绘图主体原本为内联 SVG 时直接提取；HTML/CSS 主体则使用可靠转换工具或按同一内容与布局生成 SVG，不假定任意网页能无损转换。
3. SVG 导入不受支持或效果不可靠时，使用经过核验的高清 PNG。正文保留核心结论，不能仅交付无法显示的文件。

动态交互先确定需要展示的状态，必要时输出多个静态视图，并保留筛选条件、标签和图例。静态 SVG 不承诺保留网页交互。

不要把整张截图嵌入 SVG 后宣称是可编辑矢量图；依赖 `foreignObject` 的 HTML 包装也不代表目标平台能正确渲染。生成的 SVG 应尽量使用原生文本、路径和形状。检查字体、尺寸、换行、阴影、裁切和连线，保留源稿便于更新。

这是一条提高复用效率的默认路径，不强制把已有合格画板、SVG 或图片重做为 HTML；原生协作编辑、用户指定格式和目标平台能力决定最终实现。

### 5. 制作并验证最终显示效果

先根据已确认内容直接制作，除非用户明确要求审稿或存在影响含义的歧义，不额外增加逐图批准环节。使用实际可用工具；无法使用期望工具时选择可行载体并说明限制。

检查实际文档中的显示尺寸，不只看放大的原图：

- 能否迅速识别主题、入口、主线与重点？
- 标签是否可读，阅读顺序是否明确，卡片换行与跨区连线是否无歧义？
- 连线端点、方向和条件是否准确，有无暗示了正文未证明的因果或依赖？
- 文字、数据、单位和必要限定是否与正文一致？
- 是否出现过密小字、低对比、图标遮挡、裁切或重排？
- 在灰度或无法辨别配色时，文字、形状和线型能否继续表达关系？

信息过多就拆图或移到正文，不依靠提高图片分辨率掩盖字号太小的问题。修订影响正文含义时同步调整正文。保留简短图注或替代说明，支持搜索和非视觉阅读。

## 给制作工具的任务说明

使用自然语言组织以下要素，不要求固定长提示词：

1. 图要回答的问题、读者和放置位置。
2. 必须保留的文案、数据、关系，以及不能添加的内容。
3. 布局和阅读顺序，主次路径或比较维度。
4. 视觉方向：配色、线条、图标、字体层级和留白；可附风格参考，说明只参考视觉。
5. 交付介质、实际展示尺寸、编辑与导出需求。
6. 准确性和可读性的检查项。

参考风格是表达手段。只要信息层次更清楚、关系更容易理解，可以采用与参考图不同的画风。
