# 文档写作与准出

让目标读者仅凭文档就能理解问题、判断结论，并完成文档承诺的行动。以事实可靠、理解顺畅和内容必要为标准。图文协同是写作的基本要求：主动用合适的表格、图片和流程图降低理解成本，不把复杂关系全部留给长段落。评价图表覆盖是否充分、表达是否有效，不以数量凑指标。

## 适用范围

- 遵守用户指定的受众、体裁、模板、语言和保留范围。未指定语言时，沿用待编辑文档的语言；新文档根据用户请求和目标读者确定。
- 写作或重写：完成初稿、检查、修订、准出评估。仅评审：指出问题及建议，不修改原文。
- 本 Skill 管内容质量。需要 Word/PDF 排版、飞书读写或图表制作时，使用当前可用的相应工具；不要假设工具已经安装或已获发布授权。
- 完整评审前读取 [质量量规](references/quality-rubric.md)。需要表达或图表取舍示例时读取 [示例](references/examples.md)。

## 1. 明确文档要解决的问题

先从当前请求和已有材料确定：

- 谁会读，已经知道什么。
- 读完应理解什么、作出什么判断或完成什么行动。
- 哪些内容在范围内，交付形式和篇幅是否有限制。

优先读取用户提供的材料和相关证据。目标不清或存在会改变结论的歧义时再问；已有充分信息就直接写，不把每个段落都变成确认环节。不得为了填模板而虚构需求、责任人、时间、成果或承诺。

## 2. 先确定论证和证据，再写长文

为文档建立简短的内部提纲：核心问题 → 主要结论 → 必要解释与证据 → 影响或行动。按读者理解所需的前置关系组织，不按作者调查过程排列。

同时设计视觉提纲：识别比较、流程、交互、层级、数量变化和界面操作，为适合视觉解释的关键内容安排对应图表及其位置。先明确图表帮助读者理解什么，再组织正文，不等文字写完才装饰性插图。

根据目的选择结构，不强制统一章节：

| 目的 | 建议阅读顺序 |
|---|---|
| 解释概念 | 直观定义 → 最小例子 → 机制 → 边界与误区 |
| 推动决策 | 决策问题与结论 → 约束和证据 → 选项与取舍 → 行动条件 |
| 指导操作 | 目标与前提 → 操作步骤 → 成功判断 → 必要的失败处理 |
| 描述技术方案 | 目标与约束 → 总体设计 → 关键细节 → 风险、兼容性与验证 |
| 分析或复盘 | 已确认结论 → 事实与口径 → 原因及不确定性 → 改进与验证 |

维护轻量的“关键主张—证据”对应关系，放在工作笔记中即可：

| 主张 | 性质 | 证据位置及适用范围 | 核验状态 |
|---|---|---|---|
| 会影响读者判断的事实或数字 | 事实／推断／建议／假设 | 来源、日期、版本或数据口径 | 已核验／用户提供未独立核验／待核验 |

- 优先原始材料：源码、规范、原始数据、官方文档和直接记录。用户提供的材料可以作为来源，但不自动等于事实已独立核验。
- 只引用实际读过且支持该主张的来源；文中引用靠近相应主张，避免把链接堆在结尾充当证明。
- 数字说明单位、时间范围、样本或分母，以及比较基准。区分百分比和百分点、相关性和因果性、已实现和拟实现、观测和推断。
- 会随时间变化的关键事实应当前核验。访问不到时写明证据限制；对会改变核心结论的缺口，暂停作出确定结论。
- 示例、模拟值和估算明确标注，不冒充真实结果。常识性解释、修辞和明确的建议不要求每句加引用。

## 3. 按理解顺序写作

- 开头尽快回答文档核心问题，同时补齐理解结论必需的背景。不要写没有信息的开场白。
- 每节围绕一个读者问题，每段推进一个意思。新概念先解释再使用，简称首次展开；细节依赖前面的定义和例子。
- 标题明确说明内容，层级表达包含关系，通常不超过三级。不要为一两句话增加空洞标题。
- 同一事实或解释确定一个主要位置。其他地方用简短回指；摘要可以压缩结论，但不再展开同一套论证。
- 用具体主体和动作，保留条件、范围和不确定性。减少口号、空泛形容词、机械排比、强行对比、过量加粗和“综上所述”式重复总结。
- 删除一句前先问：它是否提供新事实、必要解释、证据、限制或行动？都没有就删。不能为了简洁删掉会改变理解的前提或限定。
- 以自然连贯的段落解释因果和取舍；并列项或步骤适合列表，不把所有段落改成项目符号。

### 为长文设置阅读引导

- 对分析较多、模块较多的文章，在开篇用摘要或高亮块交代核心结论、关键依据和影响，让读者先建立全局认识。证据不足时，把当前判断及其限制一起呈现。
- 每个内容较重的章节先用一句话说明本节结论或要解决的问题，再展开证据和细节。章节已经简短明确时无需再加总结。
- 高亮块承载关键结论、决策、适用条件或重要提醒；使用简短标签和适量文字，不把整段论证装进高亮块。保持同类信息样式一致，不依靠颜色单独传达含义。
- 摘要负责全局，章节引导负责局部，正文负责论证；三者层次递进，避免把同一结论原样抄写三遍。已有摘要时，不再追加重复的结尾总结。
- 使用目标平台的原生高亮块、引用块或卡片；平台不支持时用简短的加粗引导句。遵守用户指定的正式模板和视觉要求。

## 4. 主动设计图文协同

图表是主要解释手段之一。对正文中的关键关系主动选择下列表达；存在相关内容时，应安排合适图表，或明确说明已有表达为何足够。不能以“文字已经提到”代替图表设计：

| 信息 | 优先表达 | 核验重点 |
|---|---|---|
| 多个选项、多项属性 | 对比表 | 维度一致；缺失值不写成零 |
| 步骤、条件分支 | 流程图 | 入口、分支条件、出口明确 |
| 多方交互及先后 | 时序图 | 发起方、方向、同步或异步正确 |
| 组件关系和边界 | 架构图 | 连线有含义；区分数据流与依赖 |
| 数量、趋势、分布 | 数据图 | 来源、单位、时间、坐标与基准正确 |
| 界面位置或实际外观 | 截图及局部标注 | 截图确实对应版本和步骤 |

对于较长或复杂文档，先提供合适的总览图或总览表帮助建立全貌，再用局部图表逐层解释关键细节。关键方案比较、多分支流程、多方交互、复杂组件关系或数据趋势应有对应视觉表达；缺少时视为需要修订的问题。短小且单一的事实说明可以纯文字，但不能把它推广成复杂文档的默认形式。

图表承载关系与对比，正文解释读法、因果、取舍和关键含义，不再逐项抄写图表。把图表放在相应解释附近；每张图都应有可理解的标题或说明。避免孤立大图、过密表格和没有信息的装饰图片。

先设计最清楚的信息表达，不预设 Mermaid 或 UML。定制架构图、流程图、卡片和比较图优先以 HTML/CSS 配合内联 SVG 制作可复用源稿：目标平台支持 HTML 嵌入时直接嵌入，不额外转换；不支持时优先从同一内容与布局生成静态 SVG。需要原生节点协作编辑时使用画板，简单流程或需要文本版本管理时可以使用 Mermaid／UML。普通正文、表格和高亮块保留平台原生形式，不把全文改成 HTML。

飞书文档优先利用原生画板、表格、高亮块，以及当前工具确实支持的 HTML5 内容块。需要这些富文本能力时，读取 [飞书视觉表达](references/feishu-visuals.md)，依据内容选择并验证实际呈现。其他平台采用其支持的等价能力。

科学和统计图使用真实数据及合适绘图工具，生成式图片不得充当数据、截图或事实证据。输出介质不支持所选载体时，转换成可查看的图像或等价表格，保留必要文字说明。插入或转换后检查标签、箭头、裁切、字体及交互状态；只能检查源码时明确未验证渲染，不宣称视觉验收通过。

### 文档配图设计

在视觉提纲确定后、制作主要配图前，读取 [文档配图设计](references/illustration-design.md)，将内容转成可执行的图示方案：

1. 确定图要回答的读者问题，提炼准确的图内文案、实体、数据和关系。
2. 根据内容选择分区成果图、分层架构、流程与职责并排、阶段卡片或其他合适布局。
3. 设计视觉层次、语义图标、颜色分组、连线和留白。手绘感、浅色底和插画是可选方向，不固定画风或卡片数量。
4. 定制图示优先复用 HTML 源稿：支持则直接嵌入，否则生成静态 SVG；按编辑需求选择画板。概念插画可生图，精确文字、数字和连线可独立排版，避免为不同格式重复设计。
5. 按目标文档的实际显示尺寸核验，必要时拆成总览与详图；同步修正图文不一致。

评价配图是否让主题、分组、关系和阅读顺序更容易理解，不以是否像参考图、是否手绘或是否用了生图工具计分。

## 5. 评审、修订和准出

写完后按 [质量量规](references/quality-rubric.md) 执行：

1. 检查阻塞项，先解决事实与核心逻辑问题。
2. 进行读者问题测试，检查脱离聊天上下文后是否仍可理解。
3. 对六个维度逐项评分，为扣分和高分给出文中依据。
4. 按影响修订，然后对最终版本重新评估。

评分是有依据的编辑判断，不是客观测量，也不是运行验证。不能靠改分数、增加篇幅或多放图片达到准出。

默认最多两轮实质修订；仍未达标则交付明确标注的草稿，说明剩余问题和所需证据。若用户要求继续完善且有可获取的新证据，可以继续。不要无限自评，也不要为了“通过”补造事实。

## 6. 交付

交付可独立阅读的最终文档，并在文档外附简短质检说明：

- 结论：通过／有条件通过／未通过。
- 六个维度得分及总分；关键扣分位置和原因。
- 阻塞项、剩余限制与读者测试方式、结果。

修订过程和评分默认不混入面向读者的正文。用户只要正文时，内部完成检查；若仍有影响使用的证据缺口或未通过事项，必须简短告知。不要把“文件生成成功”当作文档质量通过。
